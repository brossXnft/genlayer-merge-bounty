Bounty platforms ask you to trust them to judge “done” and to hand over the money. Here the escrow is a GenLayer Intelligent Contract written in Rust. When a contributor claims, five validators each read the pull request from the GitHub API and pay out only if they agree it was merged into the right repository, before the deadline, and closes the issue.

How it works

  1. Fund. Anyone escrows GEN on an open GitHub issue. Others can add to it.
  2. Fix. The contributor opens a PR whose description contains Closes #<issue> and a line genlayer-payout: 0x… with their address. The claim dialog writes both lines for you.
  3. Merge. The maintainer reviews and merges as usual. Merging is the acceptance.
  4. Claim. The payout wallet presses Claim. Validators read the PR from GitHub; on agreement the contract sends the escrow to that address when the transaction finalizes.
  5. Refund. If nobody claims by the deadline plus 3 days, each contributor takes back their own share.

No one judges “done”

The rule is mechanical and public: merged, right repo, inside the window, closes the issue. The maintainer's merge is the only human decision.

No custodian

GEN sits in the contract's ghost account. It can only leave to the payout address in the merged PR, or back to the people who funded it.

Independent reads

The leader's view of GitHub is not trusted: every validator fetches the PR itself and the facts must match exactly, or no payout happens.

Who can edit the payout line

Only the PR author and the repo's maintainers can edit a PR description, and only the payout wallet can claim, so a third party cannot redirect or strand the payment.
